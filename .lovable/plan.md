# Nexoras Ganesh Utsav 2026 + Refer & Earn

## Goal
Launch a reusable, automatically timed festival campaign and secure referral rewards system without changing the core study and testing experience. The Ganesh Utsav presentation will be active from **15 September 2026 00:00 through 25 September 2026 23:59:59 Asia/Kolkata**, then disappear automatically while referral history and earned credits remain.

## What will be built

### 1. Reusable campaign foundation
- Add a campaign configuration record with name, time zone, start/end timestamps, enabled state, banner/theme settings, reward amounts, and configurable eligibility rules.
- Derive `scheduled`, `active`, or `ended` from the configured timestamps on every trusted read; no recurring job is needed for expiry.
- Provide a safe public campaign summary and admin-only update controls.
- Seed **Nexoras Ganesh Utsav 2026** with rewards of **8 credits for the referrer** and **5 credits for the referred user**.

### 2. Central AI Credit wallet and immutable ledger
- The current project has no application-level AI Credit wallet or transaction tables, so create the canonical Nexoras wallet rather than a parallel referral-only balance.
- Add one balance per user and an append-only transaction ledger with referral linkage, amount, type, description, status, and timestamps.
- Restrict direct writes; balances and transactions change only through trusted database functions/server functions.
- Keep credits and ledger entries after a campaign ends.

### 3. Secure referral lifecycle
- Give each signed-in user one globally unique, case-insensitive `NEX-XXXXXX` referral code generated by the backend.
- Accept `?ref=CODE` on signup, validate it safely, and bind it once when the account is created; it cannot later be replaced or reassigned.
- Create pending referrals first. Finalize only after the referred account is email-verified, genuinely new, distinct from the referrer, unused, and eligible under the campaign rules.
- Award both sides in one database transaction: either the +8 and +5 ledger entries and balances all succeed, or none do.
- Add uniqueness constraints, idempotency keys, row locking, status transitions, and server-side amount calculation to block duplicate, concurrent, self, forged, and replayed claims.
- Record rejected/reversed-ready states without exposing personal information.

### 4. Refer & Earn experience
- Add `/refer` with the user’s code, copy button, native Share support with clipboard fallback, honest reward messaging, summary totals, and privacy-safe history.
- Send unauthenticated visitors to signup while preserving a sanitized referral code.
- Add campaign analytics for generated codes, shares, attributed signups, pending/successful/rejected referrals, credits awarded, participation, conversion, and daily activity.

### 5. Temporary festive presentation
- Add a campaign provider at the shared shell level so individual pages are not permanently modified.
- During the active window, use restrained saffron/gold accents over Nexoras indigo, subtle marigold/diya details, a light glow, and small low-cost particles.
- Add the homepage campaign banner with the exact reward copy, deadline, and **Refer & Earn** action.
- On mock tests, practice/questions, coding, interviews, and result-oriented paths, suppress decorations and show only the small **🪔 Ganesh Utsav 2026** indicator.
- Respect reduced-motion settings and substantially reduce effects on small screens. Outside the campaign window, render the normal Nexoras theme and no campaign banner.

### 6. Admin controls
- Add an admin campaign page for enable/disable, dates, reward values, eligibility settings, banner, festive theme, and referral-system state.
- Authorize every read/write requiring administration through the existing server-verified admin role; do not rely on email checks or browser state.
- Include aggregate campaign metrics only, without exposing referred-user email addresses.

### 7. Signup and verification integration
- Extend email signup to carry the normalized referral attribution into account creation.
- On confirmed sign-in/session hydration, call an authenticated idempotent finalizer; unverified users remain pending and receive no credits.
- Keep normal signup working when no referral is supplied or the campaign is inactive.

### 8. Automated validation
- Add tests for valid +8/+5 rewards, invalid codes, self-referral, duplicates, multiple-code attempts, immutable attribution, unverified accounts, idempotent retries, concurrent requests, ledger entries, pre/during/post campaign behavior, retained credits, theme expiry, reduced mobile motion, and distraction-free exam pages.
- Verify the homepage, signup referral flow, Refer & Earn dashboard, admin controls, and representative exam/practice pages on desktop and mobile.
- Run focused tests, type checks, and the database security linter.

## Technical details
- New tables: `campaigns`, `referral_codes`, `referrals`, `credit_balances`, `credit_transactions`, and privacy-minimized `campaign_events`, each with explicit grants, row-level access rules, indexes, and update protections.
- Foreign-key user references will use `public.profiles`, keeping user-facing data mapped through the application profile layer.
- Atomic reward issuance will be implemented as a locked, idempotent database function invoked only through authenticated server functions.
- Public configuration exposes only safe campaign fields. User dashboards expose only their own code, aggregate counts, and anonymized history.
- The campaign end is stored as the exclusive instant **2026-09-26 00:00 Asia/Kolkata**, ensuring all of September 25 is included without misleading countdown behavior.
